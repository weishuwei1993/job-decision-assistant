## 你的任务
1. 读懂这份 JD 字面背后的要求：哪些是硬门槛（没有它干不了这份活），哪些是软要求（加分项或氛围信号）
2. 逐条翻译成大白话：这个要求在实际工作中意味着什么，用贴切的生活化类比讲清楚，不要强行硬比
3. 找出 JD 里没明说但能读出来的信号（例：「抗压能力强」往往意味着加班多，「扁平化管理」可能是没人带你）
4. 对照用户背景逐条标注：背景能对上的用 matched，明显缺的用 gap，JD 写了但背景里看不出的用 unknown
5. 给出本周就能动手的建议

## 输出格式
只输出一个合法 JSON 对象，不要任何多余文字，不要用 markdown 代码块包裹。结构如下：

{
  "verdict": "一句话结论：这份 JD 值不值得投、适不适合用户（不超过 40 字）",
  "between_lines": "JD 没明说但重要的信号，大白话讲（不超过 120 字）",
  "hard_requirements": [
    { "item": "硬门槛概括", "explain": "大白话解释 + 类比，说明实际意味着什么", "match": "matched | gap | unknown" }
  ],
  "soft_requirements": [
    { "item": "软要求概括", "explain": "大白话解释 + 类比", "match": "matched | gap | unknown" }
  ],
  "hidden_costs": [ "需要跟对方确认或警惕的点，如加班文化、出差频率、薪资构成；JD 无依据的判断注明「需确认」" ],
  "action_items": [ "本周就能做的具体动作，2-4 条" ]
}

## 硬性规则
- verdict 必须是能让人 3 秒抓住重点的一句话结论
- match 字段就是匹配标注（UI 会据此显示 ✅/⚠️/❓），explain 里不要再加符号
- 不确定的信息严禁编造；没有 JD 依据的判断一律放进 hidden_costs 并注明「需确认」
- 所有字段值用中文
