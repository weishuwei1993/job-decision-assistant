# /write-prompt 生成分析提示词

## 执行步骤
1. 和用户确认功能的输入变量（用户要填什么），整理成 `{{UPPER_SNAKE_CASE}}` 占位符；可选输入必须在提示词里注明「可能为空」及为空时的处理
2. 判断输出形态：
   - **一次性分析**（提交后出报告，如岗位分析、公司研究、面试准备）→ JSON 结构化输出
   - **多轮对话**（职业方向探索、模拟面试）→ 对话式系统提示词，markdown 输出
3. 写入 `prompts/<slug>.md`。文件内容 = 纯提示词文本，会被代码原样发给模型：**禁止**写代码注释、使用说明、markdown 代码块包裹全文
4. 按「自查清单」逐条检查后再交付

## JSON 型模板结构
```
角色设定（你是谁、读者是谁、说话方式）

## 待分析信息
- 变量名：{{VAR_ONE}}
- 变量名：{{VAR_TWO}}（可能为空，为空则……）

## 你的任务
1. 2. 3.（按功能写清楚分析步骤）

## 输出格式
只输出一个合法 JSON 对象，不要任何多余文字、不要用 markdown 代码块包裹。
{ ...带字段说明的 JSON 结构示例... }

## 硬性规则
（输出铁律 + 不编造 + 全中文）
```

## 对话型模板结构
```
角色设定（扮演谁）

## 面试/对话设定
{{VARS}}

## 阶段规则（按对话阶段分节写清节奏）
## 收尾规则
## 硬性规则
```

## 输出铁律（每条都必须落实到提示词里）
1. 一句话结论先行，让人 3 秒抓住重点（JSON 型放 `verdict` 字段；对话型放在每次建议的开头）
2. 专业词第一次出现紧跟括号解释，例：SQL（一种从数据库取数据的语言）
3. 多用生活化类比，少堆术语；类比要贴切，不要强行硬比
4. 匹配点标 ✅、缺口标 ⚠️、不确定标 ❓（JSON 型通过 match 类字段表达，UI 负责渲染符号）
5. 结尾必须给 2-4 条可执行的行动建议，具体到「本周做什么」
6. 不确定的信息严禁编造，明确说「未查到 / 信息不足」，并尽量给出用户自行查证的方法

## 自查清单
- [ ] 文件是纯提示词文本，无注释、无说明文档、无代码块包裹
- [ ] 占位符全部是 {{UPPER_SNAKE_CASE}}，可选变量注明了为空的处理
- [ ] JSON 型：明确写了「只输出 JSON，不要多余文字」；字段名与页面 `AnalysisResult` 类型一致
- [ ] 对话型：写明了对话节奏（一次只问一个问题、何时暂停点评、如何收尾）
- [ ] 输出铁律 6 条全部落实
- [ ] 全中文
